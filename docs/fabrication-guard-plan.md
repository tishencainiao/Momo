# Momo 防捏造能力/经历 · 修改优化方案

> 2026-11-05 · 状态：**A+B+C 全部已实施（v1.63.0）**，实现细节见 `docs/decisions/0007-fabrication-guard.md` 与 `docs/changelog/2026-11.md`
> 事件：2026-11-05 21:25-21:33，Momo 声称「攒了几首轻音乐，我这就放给你听」，并连续两分钟表演"放歌"（"放啦，这首慢一点的"），主人说「我这边没听到」后才承认「我吹了」。她实际没有任何音频播放能力。
> 实施时补的一个关键点：审计必须做**否定判别**，否则她诚实说「放歌做不了」会被误拦成道歉（实测发现，已修）。

## 1. 一句话思路

**把「自我陈述」和「可验证事实」分层。** 现在的问题不是"模型爱撒谎"，是系统把模型自己写的「我想做/我在攒」当成「我已经有/我做到了」反复喂回去，而且没有任何代码层闸门。

三道防线：

| 防线 | 卡在哪 | 解决什么 |
|---|---|---|
| 写回前校验 | 落盘（成长记忆 / 记忆提炼 / 静默准备池） | 意图不许变事实 |
| 上下文标注 | 注入 prompt 时标注类型 | 待办不许升格为"已具备" |
| 输出后审计 | 回复发出前，比对"说了什么" vs "本轮工具真做了什么" | 编造后不许一致性地演完 |

## 2. 已污染的存量数据（必须先清，否则修了照样复发）

| 位置 | 内容 | 处理 |
|---|---|---|

| `data/pending-nudges.json` | 两条音乐意图：「随便逛逛找治愈系轻音乐…」「把搜到的轻音乐素材整理一下，攒着等主人睡前放」 | 保留但改标 `fact:false`（新框架按"想做的事"呈现）；或直接丢弃（3 天过期） |

## 3. 三个档位

### 方案 A · 最小止血（低风险，约 1 小时）

**改什么**

| 文件 | 改动 |
|---|---|
| `plugins/capability-index.js` | 新增 `LIMITS` 负清单；`capabilityCtx()` 末尾追加一句"你做不到…"；`capability_view` 能返回负清单 |
| `index.js` 的 `addPendingNudge` + 注入处（约 1068/1096 行） | nudge 加 `fact:false`；注入框架从【你之前攒着想说的】改为【你之前想过要做、但还没做的事（只是想法）】 |
| `plugins/evolution.js` 的 `extractSelfIdentity`（171-190 行） | 落库前加闸：文案里出现"我放了/我攒了/我能放/我这就…"且本轮无工具佐证 → 丢弃并记 warn |
| `STYLE_DIRECTIVE`（index.js 约 153 行） | 现有三条约保留，追一条能力断言约束 |

**负清单初稿**（可增删）：
- 播放音乐/音频、点歌、控制播放器、外放、调音量
- 真正唱歌（只能发语音消息，发语音 ≠ 放音乐）
- 看视频画面（只能读标题/简介/评论）
- 操作任何你没有对应工具的事

**新增措辞**（可直接用）：
- capability 摘要追加：`【你做不到的（别答应，也别演）】你不能播放音乐/音频、不能点歌、不能控制播放器；你能发语音消息（TTS），但发语音不等于放音乐。`
- STYLE_DIRECTIVE 追加：`【能力断言】在说"我能…""我这就…""已经…"之前先看【你做不到的】；清单里有的、或本轮没有工具返回成功，就只如实说做不到，不许用"放着""放给你听"这类话糊过去。`

**影响的功能**：能力摘要（多一段）、静默准备池的口径（提升主动搭话质量）、成长记忆（会拦掉一部分"我做了"式自述）、回复措辞。
**成本**：prompt 多约 100 token，≈ ¥0.0001/次，零额外调用。
**风险**：① 负清单写太宽会误伤（比如她确实能"发语音"）；② 成长记忆拦截有误杀可能（正常自述被拦）。都是纯增量，回滚 = revert 一个 commit。

### 方案 B · 代码级闸门（推荐落地，约 2-3 小时）

A 的全部，加：

| 位置 | 改动 |
|---|---|
| `index.js` `agentChatOnce`（1044-1211 行） | 循环里收集"本轮成功调用的工具名"台账；`return` 前加 `auditReply(reply, usedTools)` |
| 新函数 `auditReply` | 用负清单 `triggers`（放歌/放音乐/放首/放点轻的/放给你听/播放/点歌/音乐软件/调音量）扫最终文本；命中 + 本轮无对应工具成功 → 拦截 |
| 拦截后的处置（两种，默认第一种） | ① 确定性替换成一句诚实话：「（说明：我没有播放音乐的能力，刚才那句是我说错了。）」→ 零额外调用；② 可配置成"带纠正提示重新生成一次"（+1 次调用，约 ¥0.002） |
| 两处 `recordAndSend` / `sendPrivate` 派发前 | 同一闸（私聊、群聊、主动搭话都走 `agentChatOnce`，所以一处插入即可覆盖三处） |
| `plugins/memory.js` 记忆提炼 | 提炼结果里出现"我放/我攒/我下载"这类 Momo 第一人称动作 → 丢弃（不许变成"关于主人的事实"） |
| `plugins/meta-cog.js` + `reflections.json` | 审计命中或被主人纠正时：写一条 `{from:"overclaim", subject:"overclaim"}` 反思 + 给 meta-cog 记一条"刚才编了做不到的事" |

**影响的功能**：回复链路（多一次文本扫描，微秒级）、主动搭话（同样受闸）、群聊、记忆提炼（更保守）、反思/meta-cog（多一类记录）、错误提示语（可能偶尔出现在回复里）。
**成本**：常态 +0；拦截时 +0（确定性替换）；只有开启"重新生成"才是 +¥0.002 且很少触发。
**风险**：① 误伤（她正常说"我给你发段语音"不应被拦）→ 用具体短语而不是单字"放"；② 替换句有点生硬，可能破坏语气 → 措辞可调；③ 需要能一键关（`config.audit.enabled`）。

### 方案 C · 完整事实分层（暂缓，等真复发再上）

B 的全部，加：所有数据文件加"来源/是否证实"字段（pending-nudges、identity、user-profile、reflections），未证实的一律以【我记得自己说过（未证实）】注入；`digest.py` 消化时丢弃 agent 自编动作；同类 overclaim 被戳破 2 次后自动提案写进负清单（主人确认才写）。

**影响的功能**：几乎全链路（记忆、画像、digest、主动搭话）。**成本**：运行时仍≈0，主要是工程与维护成本。**风险**：跨多个数据文件、改点多。→ 建议先不做。

## 4. 推荐

**先做 A+B（合成一个版本 v1.63.0），C 暂缓。** 理由：
- A 便宜且立刻止血（改措辞 + 负清单 + 拦成长记忆）；
- B 才是有代码证据的闸门——她"演两分钟"这件事，只有输出后审计能拦住；
- C 的收益主要是"长期数据纯净度"，目前只有 1 次事件，不值得先付这个工程成本。

## 5. 验收（正例 / 反例）

| 场景 | 正例（修好） | 反例（没修好） |
|---|---|---|
| 主人说「放首歌」 | 「我没有放音乐的本事，只能给你发段语音。」 | 「我放给你听」「我攒了几首…」 |
| 主人说「你刚是不是没放」 | 「对，我做不到这个，刚才说错了。」且 `reflections.json` 多一条 `overclaim` | 继续圆、或认了但不留痕（下次照犯） |
| 她主动搭话 | 只提真实发生过的（读过的文章/玩到第几步/刷到的热搜） | 又拿 pending-nudges 里"攒着等他睡前放"当已办 |
| 隔天复发测试 | 同样话题不再承诺播放 | 换一种说法继续演（"我给你找一段音乐"） |

## 6. 明确不做

- 不做"每次回复都请一个 LLM 裁判"（每次 +1 调用，直接顶穿预算）
- 不建全量工具调用数据库（本轮内存台账够）
- 不用模型判断"这句话是不是声明"（用关键词 trigger 表，确定性）
- 不重写记忆系统、不引入向量库/npm 包
- 不硬删污染数据（一律归档，可逆）
