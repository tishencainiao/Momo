## 八、主刀返修中发现并修复的反例

- 主动发送在真实发送前写 proactive 成功日志 → 改为成功后才写。
- life 查询沿用当天旧 phase、冷却读取错误状态对象 → 改为即时 tick 并读取持久状态。
- 旧行动状态写盘异常仍返回 acquired → 改为失败关闭；结算失败保留防重入锁。
- autonomy 只检查 basename，误接受 `../self-x.js` → 改为只接受插件目录内纯 self-* 文件名。
- evolution 自动/批准写生产插件缺行动闭环、watch 失败可能留文件 → 增加 begin/end、失败删除与账本缺失门禁。
- 内部心智动作只有候选评分，没有日上限与结果证据 → 接入 life/action-intents，区分成功/失败/未知。
- 日目标可在空证据下标完成 → 改为必须有结果证据。

## 九、诚实限制与 DSH 复验重点

1. 隔离 manifest 冒烟只加载模块形状，不执行 init/tools/hooks；它不是防御任意恶意代码的通用安全沙箱。
2. stable digest、scope、证据和修订链是约束模型自述的机制，不等于模型永远不会生成错误内容。
3. 日计划、冷却和内部动作上限已做时间注入模拟，尚未经过真实多日观察。
4. 请 DSH 独立重跑全量测试与四份 v3 定点矩阵，并重点复测 A01、A03、A08、G06、G07、G09 和路径穿越反例。
5. 真实重启后核对 bridge.log 的 56 插件、startup-recovery.json 和 health 快照；未重启前不得把 S07 写成已通过。
