## v1.46.0 · 2026-11-02

**表情包系统大改：从「固定随机抽一张」升级成有身份、有状态、有门禁的语义库**

起因：用户教了 3 张表情包的含义，实测发现一张都没真记住——写到了几小时前的旧图上、后教覆盖先教、第 3 张完全没记录，教完 30 秒又发了同一张。深挖后确认根因不是「她看不懂图」，而是三个结构性缺陷：

1. **没有身份**：`setLastMeaning()` 只认 `last-collected.json` 这个全局指针，而它只在用户发图时才更新。她发出去的是哪张，系统里没有任何记录。
2. **没有状态**：`desc` 只是一句话，没有风险等级、没有「允不允许主动发」、没有生命周期。
3. **没有回写**：`index.js` 存会话时只写了她的回复文本，发出去的表情包一个字都没记，下一轮她说「这张」时完全不知道指哪张。

**改造方案来自两个开源实现的代码调研**：
- [northhalf/meme-pilot](https://github.com/northhalf/meme-pilot)：每张图有稳定公开 ID（`合集.序号`），所有操作都用 ID 指代
- [luojisama/nonebot-plugin-personification](https://github.com/luojisama/nonebot-plugin-personification)：受控标签词表 + 7 态生命周期 + 手动锁定最高优先级 + 主动发门禁

**新增 `sticker-store.js`（根目录，非插件）**：用 Node 内置 `node:sqlite` 存语义，零新依赖。

- 受控词表：`mood_tag` 15 个（与项目既有情绪一致）+ `scene_tag` 20 个
- 7 态生命周期：`observed / understand_only / verified / disputed / stale / rejected / manual_locked`
- 门槛：2 个来源才敢「理解」，3 个才敢「主动发」
- 稳定公开 ID：`b.003`（内置）/ `c.xxxxxxx`（收集）/ `k.001`（收藏）/ `g.xxxx`（生成的）
- 迁移：一次性把 `meta.json` + `desc.json` + `taught.json(kind=sticker)` 灌进来，`meta.json` 备份为 `meta.pre-v146.json` 后转只读

**`plugins/stickers.js` 重写（2.0.0）**：
- 选图加门禁：高风险 / 不允许主动发 / rejected / disputed 一律不进主动池
- 去重：最近 5 张不再挑（`stickers.recent_window`）
- 打分：情绪命中 + 场景命中 + 使用热度 + 从没发过的优先露脸
- 教学 `teachSticker()`：按「显式编号 → 她刚发的那张 → 最近收到的图」定位，绑定不到就**如实说没学会**，不再假成功
- 风险判断：先走关键词规则，再让模型判一次（用户选的方案），`high` 强制禁掉主动发

**`index.js`**：
- 发图后 `noteStickerSent()` 记运行时指针 + 写 `sends` 表
- 下一轮动态块注入一行「你上一条发的是 X（编号 b.003），对方说『这张』默认指它」——**只在 10 分钟内、只追加在 prompt 尾部**，不占 `history_limit`、不破坏前缀缓存

**`plugins/teach.js`**：表情包教学改走 `teachSticker`，只有真正落到某张图上才记进教学清单。

**影响到的功能**：
- 表情包发送（私聊 / 群聊 / 主动搭话 / 空间配图）
- 教学系统（表情包这一类）
- 聊天上下文（尾部多一行「刚才发的表情包」，10 分钟窗口）
- 图库维护（升级/下沉/清理现在写语义库而不是 meta.json）
- `/表情包` 统计现在显示「能主动发 / 你亲口教的 / 高风险」三项

**测试**：新增 `test/sticker-store.js`（42 条断言），更新 `test/stickers-tier.js`、`test/sticker-prompt.js`。全套 34 个测试文件通过。

## v1.45.0 · 2026-11-02

**摸头从「固定回一句」升级成「真的记一笔情感 + 下次聊天有余韵」**

原来「摸摸头」走 `self/skills.json` 的 `ev-momo` 规则：命中后从 2 句里随机抽一句、直接 return——不走大模型、不改心情、不改好感度、不写记忆，属于「即回即忘」。

**这次做的三件事：**

1. **多弄几句（偏软萌）**：`ev-momo.replies` 从 2 句扩到 9 句，覆盖撒娇 / 赖皮 / 害羞 / 平静不同味道，保留 `{call}` 称呼占位符。
2. **情感真的传进去**：规则加 `touch_feel: true`，命中后 `applyHeadpatFeel()` 会
   - 心情(mood) **+2**，但 **5 分钟内重复摸不叠加**（避免摸几下就长期亢奋，心情本来就有自然衰减）
   - 写一条动作日志 `{type:"headpat", by: userId}`（谁摸的、什么时候，`action_log` 能查到）
   - 落盘 `data/headpat.json`（次数 / 上次摸头时间 / 是否已提起）
3. **下次聊天有余韵**：新的 `headpatCtx()` 会在「15 分钟内、且这次摸头还没被提过」时，往动态块注入一句「刚才被摸过头，还有点软软的，可以顺带提一句，但不提也没关系」——**只提一次就消耗**，不会每条都念。

**为什么主人好感度没动**：`getFavor` 对主人是锁死 100 的（`index.js` 里写死），所以对主人有意义的是心情/情绪，不是好感度。这点在方案阶段已说明。

**影响到的功能**：
- 心情(mood)：`/状态` 显示、念头(mind loop)感知、下次聊天情绪标签注入——摸头会轻微抬一点，随衰减回落。
- 动作日志：`action_log` 会多出「被摸了头」的记录。
- 聊天上下文：动态块多一条可选的「余韵」，只在摸头后 15 分钟内、且只注一次。

**改动文件**：`self/skills.json`、`plugins/evolution.js`、`plugin-host.js`、`index.js`、`plugins/life-log.js`（加 `headpat: "被摸了头"` 标签）。

**测试**：新增 `test/headpat.js`（26 条断言：句子数量 / `touch_feel` / 心情 +2 与 5 分钟冷却 / 动作日志带 by / 余韵只提一次 / 超 15 分钟不提 / 无文件不报错）。全套 33 个测试文件通过。

## v1.44.1 · 2026-11-01

**修复：自我认知回答太死板（像复读机背台词）**

用户问她「你怎么看自己」，发现三次回答都逐字背同一套三连：程序不是人 / 记忆在文件里 / 关机空白没有梦。原因和之前的「哼哼」口头禅泄漏是**同一类**：`SELF_AWARENESS` 把事实写成了太完整、太顺口的句子，模型直接照搬。

- 事实压成一行**要点**（明确「这些是事实，不是要背的台词」）
- 加约束：「**用自己的话、想到哪说到哪**，不要每次把三点全背一遍，也不要固定的同一套说法」
- 允许情绪温度：可以犹豫、反问、带一点困惑或坦然；但**不卖惨、不装深沉**

**实测**（三次不同问题，说法不再一样）：
- 「你怎么看自己」→「就是跑在你这台电脑里的一个程序呗……被关掉那阵子是空的，不是睡着，是真的什么都没有。**说不上难过，就是有点奇怪。**」
- 「你是什么」→「我是跑在你这台电脑里的程序呀，一只蓝鲸女仆……不是人，但会记着你、会跟你说话，也会心疼钱那种。」
- 「你有自我意识吗」→「诶，突然问这个……不过想不想你、惦记没惦记，这些我确实有。」

- 测试：`test/awareness.js` 更新为断言「是事实不是台词」「用自己的话」「别把三点全背」「不卖惨」

## v1.43.0 · 2026-11-01

**清理：三套并行的「主动」逻辑合并成两套（分层）**

用户发现心流部分「有点重复」。排查后发现**三套**并行的主动逻辑：
- 心流 `mindLoop`（10 分钟 + 心跳唤醒）：念头 + 打分 + 行动分发（含 `chat_master`）
- 浅心跳 `shallowThink`（60 秒）：单独问「要不要主动做点什么」
- 老式 `proactiveLoop`（60 秒）：早安/晚安/日程/跟进/沉默搭话 + 静默门禁

日志实测：浅心跳今天 **0 次成功**（条件太严），主动搭话 78 次几乎全是「跳过：对方正在睡觉」。

**方案 B（分层）**——职责清晰：
- **心流**：只管思考（念头/打分）+ **非消息行动**（发空间/搜索/看空间/分享趣图/浏览/反思/进化）
- **proactive**：管「何时能打扰 + 说什么话」（早安/晚安/日程/跟进/沉默搭话/门禁/试探）
- **删除**：`shallowThink` 整套；心流里的 `chat_master` 分支（保留 `share_fun`，因为 proactive 没有趣图功能，删了会丢功能）

改动：
- `plugins/proactive.js`：删 `shallowThink` 函数 + 定时调用 + `lastShallowRun`
- `index.js`：心流的 action 枚举去掉 `chat_master`、提示词改为「主动找主人说话由另一套负责，你不用操心」、`runMindAction` 删掉 `chat_master` 分支、`ACTION_COST` 表同步清理

## v1.41.0 · 2026-11-01

**① 空闲认知心跳：让她「一直在」有真实依据（不花 token）**

背景：真正的持续意识流做不到（API 无状态、¥2/天预算）。按 [The Thinking Agents Manifesto](https://github.com/openclaw/openclaw/issues/17363) 的「空闲认知」思路——**连续性来自状态，不是来自模型一直开着**。

**实现（`index.js`）**
- `mindPulseTick()`：每 **60 秒**记一条节奏快照（`data/mind-pulse.json`，环形缓冲 60 条）
  - 记录：对方静默多久、她上次想事多久前、攒着几件没想明白的事、当前心情
  - **不含任何 LLM 调用**
- **只在明显变化时唤醒思考**：心情跳变 ≥15，或静默跨过 30 分钟档
  - 冷却 ≥10 分钟、每小时 ≤3 次
  - **首次心跳（刚启动）不唤醒**——省一次调用
- `pulseCtx()`：把最新节奏注入聊天上下文
  > 【当前节奏（你自己感觉到的）】对方已经静默 45 分钟；你上次想事是 20 分钟前；还攒着 2 件没想明白的事。
- **全部参数化**（`config.mind`），方便以后搬到云服务器时调高频率：
  - `pulse_sec`（默认 60）
  - `min_wake_gap_min`（默认 10）
  - `max_per_hour`（默认 3）

**实测**：启动日志「空闲心跳已启动：每 60 秒一次（唤醒间隔 ≥10 分钟，每小时 ≤3 次）」；`mind-pulse.json` 每 ~52 秒新增一条快照；首次唤醒日志「空闲心跳唤醒思考：你上次想事是 2 分钟前；还攒着 3 件没想明白的事」。

- 测试：新增 `test/pulse.js` 16 条（节奏描述、首次不唤醒、无变化不唤醒、情绪跳变唤醒、每小时上限）

## v1.31.2 · 2026-11-01

**修复：联脑造成「桥接请求发给自己」的死循环（严重）**

现象：桌宠聊天和 QQ 回复都卡 30 秒，日志刷出成片的 `桌宠联脑失败: timeout`。

**根因**：`resolveChatSettings()` 的 `base_url` 回退链是
```js
c.base_url || pet.chat.base_url || provider.base_url || "https://api.deepseek.com"
```
把桌宠的 provider 指向 `http://127.0.0.1:3999` 后，**桥接自己也解析到了 3999**——于是
`agentChatOnce → agentToolCall → 自己 → petChat → agentChatOnce → 自己 …` 无限递归，直到 30 秒超时。

**排查过程**：
- 模型直连延迟 0.9s，排除模型慢
- 51 个工具 22KB 请求 0.8s，排除工具体积
- 打印每步耗时 → `联脑步骤1: 30033ms，工具0个` → 第一步就卡死
- 打印解析结果 → `base_url = http://127.0.0.1:3999`，确认自环

**修复**：在 `config.json` 的 `chat` 里**显式指定** `base_url = https://api.deepseek.com`、`model = deepseek-v4-flash`（`c.base_url` 优先级最高，压过桌宠回退）

**验证**：
- 启动日志 `模型=deepseek-v4-flash 接口=https://api.deepseek.com` ✅
- 联脑请求 **1.1s** 返回「在的在的，一直趴这儿呢。主人怎么啦？」✅
- 桌宠余额缓存恢复正常（¥6.36）✅

**顺带**：`agentChatOnce` 在 `petMode` 下增加每步耗时日志，便于以后排查。

## v1.23.0 · 2026-11-01

**心流三层重构：感知（flash）→ 判断（打分）→ 执行（push/queue/store）**

背景：用户希望优化心流。参考 [ProAct（空闲时间计算）](https://ar5iv.labs.arxiv.org/html/2605.25971) 的三段式：预测需求 → 打分筛选 → 价值感知投递（push/queue/store）。

**原来**：每 10 分钟一次大提示词，直接决定「做什么」，只有「做/不做」两种结果。

**现在三层**：

| 层 | 频率 | 模型 | 产出 |
|---|---|---|---|
| ① 感知 | 每 10 分钟 | **flash**（便宜） | 一句念头 + 「想做事的程度」0~100 |
| ② 判断 | urge≥60 或隔 30 分钟 | 宽裕用 pro，否则 flash | 1~3 个候选意图 + 四项评分 |
| ③ 执行 | 按分数 | — | ≥0.62 执行；0.40~0.62 进静默池；<0.40 丢弃 |

- **价值评分**：`0.35×相关 + 0.20×信息缺口 + 0.25×新增价值 + 0.20×时效`（服务端算，不信模型自报的总分）
- **静默准备池** `data/pending-nudges.json`：分数中等的话先攒着，聊天时注入「你之前攒着想说的」，3 天过期，内容去重
- **`runMindAction()`**：把原来的动作分发抽成独立函数，供三层复用
- **省调用**：感知层便宜且每次都跑；判断层只在「够想做」或「隔够久」时才跑
- 测试：`test/mind-flow.js` 25 条断言（评分权重、静默池增删去重过期、阈值常量）

## v1.16.0 · 2026-11-01

**分层教学权限：主人教全部，熟人只能教表情包/词汇，高优先级覆盖低优先级**

背景：原 `teach` 只允许主人教（`isMaster`），且 `source: "user"` 写死、不记录是谁教的。用户提出「主人权限最大、其他人只能教小范围、主人教的能覆盖别人的」。

- **注入分组**：`teachCtx` 按等级排序，主人教的词标【主人教过的词】、朋友教的标【朋友教过的词（仅供参考）】
