## v1.15.4 · 2026-10-31

**成长记忆按人隔离：Momo 能分清「这条记忆是关于谁的」**

问题：成长记忆（`identity.json`）是全局列表，把和不同人的互动混在一起（「对方的饺子」是朋友、「主人发呆看灯」是主人），且注入时不管当前跟谁聊都全塞进去，导致串人。

- **`identity.json` 结构升级**：从字符串数组改为 `{text, from}` 对象（`from`=这条成长记忆来自和谁聊）；已迁移 50 条旧数据为 `from=0`（通用）
- **`plugins/evolution.js`**：`selfIdentityList()` 兼容新旧格式（始终返回字符串）；新增 `selfIdentityListFull()`；`extractSelfIdentity` 写入带 `from`，`adoptSmall` 写 `from=0`，`evaluateProposals` 兼容对象
- **`index.js`**：`evolIdentityText(userId)` 按当前用户过滤——只注入 `from=0`（通用）或 `from=当前用户` 的条目，其他用户的不注入
- 效果：跟主人聊时，只带「关于主人的成长记忆」+ 通用自我认知，不再混入「关于朋友的」

## v1.15.3 · 2026-10-31

**修「小结串人」：主人和朋友的事不再混在一起**

现象：小结里出现了「和其他用户聊天的内容，却说成是主人的」。

根因：`journal.json`（成长记录日志）是全局的，不记录「这条来自和谁聊」，而 `extractSelfIdentity` 对主人和朋友都跑、写入时不带用户标识。小结生成时把全部条目当成「和主人的」，模型分不清「主人」和「对方」，就把朋友的事安到主人头上。

- **`plugins/evolution.js`**：`extractSelfIdentity` 增加 `userId` 参数，`journalAppend` 的 identity 条目加 `from` 字段
- **`index.js`**：代理与调用点把 `userId` 传下去
- **`plugins/evening-report.js`**：`buildSummary` 给每条标注「和主人 / 和朋友」，提示词明确「主人的事和朋友的事要分清」

## v1.15.1 · 2026-10-31

**修「时间差误判」导致的上下文脱节**

现象：Momo 18:18 主动说「章鱼有三颗心脏」，用户 18:23 回「666」，她却回「我还没说啥呢」。

根因：`msg-times.json` 只记录**用户**发消息的时间戳，Momo 主动发的消息（`recordAndSend`）不更新它。于是用户 5 分钟后回复时，系统把时间差算成「4 小时 46 分钟」（距离用户上次主动说话），`timeAwarenessCtx` 据此注入「主人 4h46m 没理你」，和「5 分钟前刚发了章鱼」矛盾，模型被误导。

- **`recordAndSend()` 现在也调用 `saveMsgTime(userId, now)`**，让主动消息更新时间戳——时间差改为反映「最近一次真实互动」，不再是「距离用户上次发消息」

## v1.14.3 · 2026-10-31

**修 prompt 缓存命中率低：动态内容放到了前缀里**

现象：DeepSeek 用量面板显示 Momo 的 prompt 缓存命中率很低，输入几乎全按「未命中」计费（未命中 $0.15/M vs 命中 $0.003/M，差 50 倍）。

根因：DeepSeek 缓存是**前缀匹配**，一处不同后续全废。而 `agentChatOnce()` 的消息顺序是「人设 → **当前时间（含 HH:MM，每分钟变）** → 风格 → 处境 → 记忆 → 情绪 → 活动 → 好感 → 任务上下文 → 历史 → 用户」。第 2 条每分钟变化，导致人设之后的所有内容（含几十条历史）**一次都命中不了**。

- **重排消息顺序**：稳定前缀（人设 + 说话风格 + 处境 + 表情包摘要）→ 对话历史 → 动态块（记忆索引/相关记忆/时间/情绪/活动/好感/任务上下文合并为一条 system，放在历史之后）→ 用户消息
- **`timeDirective()` 降频**：从「日期 + 星期 + HH:MM」改为「日期 + 星期 + 时段」，并提示「不确定具体几点就说『这会儿』，不要编钟点」——不再每分钟变化
- **`coreContextMessages()` 同样修正**：原来第一条就是时间，改为末尾（影响主动搭话/浅心跳等后台调用）

预期：可命中前缀从「几百 token」变成「稳定块 + 全部历史」，输入成本可降一半以上。

## v1.14.2 · 2026-10-30

**修「让你猜但没说猜什么」——禁止编造经历**

现象：21:19 Momo 主动说「我刚看剧学了个新招，回头讲给你听」，被追问后先提示「跟吃有关」，用户猜「大米饭」又改口「跟收拾东西有关」，最后谜底是「盒子竖着放」。同一时刻还给另一位用户发了「剧里学了个新词：饭桶」。

根因：**「看剧学了个新招」本身是虚构的**。日程里的「19:00 看剧学新东西」只是背景设定，被她当成了真实经历，之后只能持续编细节圆谎。

- **`index.js` 的 `STYLE_DIRECTIVE` 新增【不许编造经历】**：不要声称「我刚看了剧 / 学了个新招 / 刷到个视频」这类具体虚构经历；日程只是背景，不是真实经历过的事；没有真实内容就别装，更不要为圆谎继续编细节
- **`plugins/proactive.js` 改 followup 意图**：原来要求「再提一下」，现在改为「有真实话头才提，没有就正常打招呼，不要编造新话题或假经历」
- **`self/identity.json` 清理坏记忆**：移除「我学会卖关子逗人猜，觉得这样聊天更有趣」（50 → 49 条），避免进化层继续强化这个行为

## v1.13.0 · 2026-10-30

**用户状态系统升级：状态会被记录、会真的挡住主动搭话**

背景：用户 08:22 说「我先睡了」，Momo 在 08:57 / 09:36 / 10:07 / 10:37 连续主动搭话。排查发现两个缺口——状态被下一句话误清，且主动搭话从不读状态。

- **规则层识别状态**（确定性，不靠模型）：`我现在要睡了/晚安` → 睡觉 **6h**；`午休/眯一会` → 午休 **2h**；`上班/加班` → 工作 **2h**；`学习/看书/复习` → 学习 **1.5h**；`出门/在路上` → 外出 **2h**
- **修复误清**：以前「收到任何消息 + 状态含睡」就清空，导致「我先睡了」→ 下一句「待会再见」就把状态清掉。现在只在**明确回来**（我醒了/起床了/回来了/下班了）时清除
- **静默门禁**：`proactiveLoop` / `shallowThink` 读状态，静默窗口内直接跳过并写日志
- **窗口过后只试探一次**：发一句「睡醒了吗 / 午休醒了没 / 忙完了吗」，发完标记 `probed`，不会反复问
- **模型不再覆盖规则状态**：`extractCurrentStatus` 遇到规则层设的静默状态直接跳过
- **日程/未完话头候选走大脑决策**：先问模型「现在适合发吗（考虑时间/对方状态/是否必要）」→ yes 才生成正文
- **Momo 自己在忙则顺延**：正在发空间/上网/进化时跳过本轮主动
- 新增 `test/status-rules.js`（12 条断言，含「待会再见」不误清）

- **阶段 3 ReAct 循环**：`agentChatOnce` 一次请求最多 6 步「思考→调工具→看结果→再思考」，隐私/权限动作（截图、电脑操作）仅主人可用
- **阶段 4 轻量 RAG**：长期/短期记忆按「关键词重叠 + 命中次数 + 时间衰减」检索 top 8/5 注入（无 embedding 接口，按方案妥协）
- **阶段 5 目标系统**：`goals.json` 长期目标 + 推理模型生成「今日小目标」，心流注入；`/目标`、`我的目标是X`
- **阶段 6 多智能体**：长问题（>60 字带问号）触发「感性温柔 + 理性务实」双视角会诊再合成，每天限 5 次

### 聊天拟人化
- **第一层 声音锚定**：STYLE_DIRECTIVE 增加 5 条 Momo 风格示例（few-shot「模仿风格不模仿内容」）+ 防 AI 味禁令 + 每情绪口头禅
- **第二层 情绪引擎**：情绪惯性（旧 30–40% + 新 60–70%）、单条消息最多跨半档、15 情绪表达规则（`EMOTION_STYLE`）、生气≥80% 强制「生气→委屈→平静」三步回落、情绪**常开注入**聊天（原先仅心情分≥5 时注入）

### 功能
- **余额查询**：`/余额` + `check_balance` 工具（DeepSeek `/user/balance`）
- **截图**：`/截图` + `take_screenshot` 工具（PowerShell 截屏，仅主人）
- **语音转文字**：QQ 语音消息 `fetch_ptt_text` 转文字后正常理解
- **定时提醒**：分钟/小时/天后、明天/今晚/明早 X 点；`/提醒`
- **每日复盘**：默认 22:30 给主人发今日小结
- **生日**：「我的生日是X月X日」记录，当天自动祝福；`/生日`
- **群友区分**：记住群名片与聊天次数，群回复注入「对方是群友『X』」
- **主动分享趣图**：心流新增 `share_fun`（抓趣图 + 俏皮话）
- **生成表情包**：`/做表情包 <描述>`（pollinations.ai 免费生图，自动入库）
- **群聊风格**：GROUP_DIRECTIVE（1~2 句、口语化）+ 群回复 max_tokens 压到 250
- **群聊防抖合并**：按「群+人」3 秒防抖、最多 8 秒合并多条消息一起回

### 修复
- **「变傻」三连**：主动搭话内容去重（`textSimilar`）、当前状态 2 小时过期、情绪判断去掉无聊度污染、「无聊/平静」不自动发表情包
- **`parseMemoryJson` 支持 JSON 数组**（此前只认 `{...}`，导致今日计划静默失败）
- **`bot.json` BOM 修复**（`EF BB BF` 导致 NapCatQQ Desktop 报 `bot config JSON failed`，Bot 列表为空）
- **名字问题**：主人/访客两套人设 → 统一为一套基础人设 + 按人「称呼规则」；`identity.json` 补「我叫 Momo」兜底
- **短期记忆 TTL** 3 天 → 7 天
- **心流频率** 30 秒 → 10 分钟（0~7 点 1 小时一次；试过 1 分钟已回退）

### 人设与权限（双层限制）
- 人设统一：基础人设（桌宠 `default_system_prompt`，含名字/生日/性格）对所有人一致，仅称呼规则按主人/访客区分
- 访客额外一行「权限认知」（电脑/QQ 操作仅主人可用，被要求时自然婉拒）——**仅影响言语**
- 权限硬校验保留在代码执行点（`isMaster()`），提示词不作为安全边界
