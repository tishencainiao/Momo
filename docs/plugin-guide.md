# Momo 插件开发指南（Manifest 规范）

> 本文是 Momo 插件平台的**唯一规范入口**：新插件（含进化层 self-*.js 自改代码）必须遵守。
> 体检脚本 `scripts/plugin-doctor.js` 按本文规则逐项校验，`check.js`（pre-commit）与 `/插件体检` 命令都复用它。

## 1. 命名规范（领域-用途）

- 插件 `name` 用 **`领域-用途` 两段式 kebab-case**，小写连字符，只含 `[a-z0-9-]`。
- 示例：`pet-body`（pet 领域 + body 用途）、`memory-digest`、`group-info`、`budget-report`。
- `name` 是机器名，**永久不变**（迁移、依赖、`requires`、`apis.get()` 都以它为准）。
- 给「人看」的友好中文名放在 `displayName`，不放在 name 里。

## 2. Manifest 字段（放 module.exports 里，与代码同文件）

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ 红 | 机器名，领域-用途 kebab-case，唯一 |
| `version` | ✅ 红 | semver（`1.2.3`） |
| `displayName` | ✅ 黄 | 友好中文名，给面板/报告显示 |
| `description` | ✅ 黄 | 一句话说清「这个插件干嘛的、什么时候用」 |
| `engines.kernel` | 选 | 依赖的内核版本（`>=1.81.0` / `^1.80.0`），不写=不限制 |
| `requires` | 选 | 依赖的 api 命名空间数组，如 `["search","body"]`（缺依赖=红） |
| `permissions` | ✅ 黄 | 用到的 ctx 能力清单（`_ctx.xxx` 的名字），体检会静态扫描核对 |
| `settings` | 选 | 可调参数，每项 `{key,label,type,default,desc}` |
| `attribution` | 选 | 借鉴来源归因 `{source,license,note}`（借鉴开源必填，见第 6 节） |
| `api` | 选 | 导出给其他插件的函数，**必须嵌套** `api:{<ns>:{fn1,fn2}}` → 别人 `apis.get("<ns>").fn()` |
| `apiSpec` | 有 api 必填（缺=黄） | api 的输入/输出契约（OpenAPI 精简版），见 2.1；面板/大脑/体检三处自动派生自描述 |
| `init(ctx)` | ✅ 红 | 接收 ctx，模块级 `let _ctx` 保存 |
| `tools` | 选 | OpenAI function-calling 工具，每项 `{def:{type,function:{name,description,parameters}}, handler}` |
| `commands` | 选 | 斜杠命令，每项 `{key,regex,handler}` |
| `hooks` | 选 | `startup/timer/private_message/group_message/reply`，对应函数 |

**最小模板：**

```js
/* 插件：你的显示名 —— 一句话用途 */
let _ctx = null;
const fs = require("fs");
const path = require("path");

module.exports = {
  name: "my-tool",              // 领域-用途 kebab-case
  displayName: "我的工具",
  description: "做什么、什么时候用",
  version: "1.0.0",
  permissions: ["DATA_DIR", "getSetting", "log"],   // 用到的 _ctx.xxx
  init(ctx) { _ctx = ctx; },
  api: { myTool: { doThing } },                     // 嵌套 api（给别人用）
  tools: [ /* {def,handler} */ ],
  commands: [ /* {key,regex,handler} */ ],
  hooks: { timer({ now }) { /* 每秒触发，记得节流 */ } },
};
function doThing() { return "hi"; }
```

### 2.1 apiSpec 写法（能力自描述契约）

`api` 里的函数是「裸函数」，别人（面板/体检/大脑）不知道它能干嘛。`apiSpec` 就是这份契约——**有 `api` 就要写 `apiSpec`**，命名空间和函数名必须与 `api` 一一对应。

```js
api: { mind: { loadMindState, saveMindState } },
apiSpec: {
  mind: {
    loadMindState: { input: "无", output: "{thoughts,last_think}", sideEffect: "只读" },
    saveMindState: { input: "state", output: "boolean", sideEffect: "写 data/mind.json" },
  },
},
```

- `input`：入参（人话描述，无则写 `"无"`）
- `output`：出参（人话描述）
- `sideEffect`：副作用（`只读` / `写盘` / `联网` / `花钱` / `改内存不落盘` / `无`）

体检判定：有 `api` 但缺 `apiSpec`=🟡；`apiSpec` 描述了不存在的命名空间=🔴；`input` 和 `output` 都空=🟡（自描述无意义）。`capability-index` 的 `describeApis()` 会从这里自动汇总「每个插件能干嘛」。

## 3. 关键约定（避坑）

1. **api 必须嵌套**：`api:{<ns>:{...}}`，不要平铺 `api:{fn1,fn2}`——平铺会让 `apis.get("<ns>")` 返回 undefined（M7 踩过这个坑）。
2. **路径/常量用懒加载**：`const F = () => path.join(_ctx.DATA_DIR, "x.json")`，别在模块顶层 `path.join(_ctx.DATA_DIR,...)`（模块加载时 `_ctx` 还是 null，会崩）。
3. **`requires` 只写 api 命名空间**，不是文件名；交叉校验看「有没有插件导出这个 namespace」。
4. **timer 每秒触发**，做每日/定期任务必须自己节流 + 记「今天已跑」状态（参考 report.js / plugin-doctor.js）。
5. **主人专属**：handler 里 `if (!_ctx.isMaster(userId)) return "..."`，没有自动的 masterOnly 字段。
6. **权限与代码一致**：`permissions` 写你真实用到的 `_ctx.xxx`，体检会扫描源码交叉核对。

## 4. 体检规则（plugin-doctor.js 判定口径）

| 级别 | 判定 | 举例 |
|---|---|---|
| 🔴 红（硬不满足） | 缺 name / name 非 kebab-case / name 重复 / 缺依赖 / api 命名空间冲突 / 工具 schema 非法 / 加载失败 | `requires` 的 ns 无人提供 |
| 🟡 黄（软不满足） | 缺 displayName / description / version / permissions 等元数据 | attribution 缺 license |
| 🟢 绿 | 全部合规 | — |

- 红项：`check.js` 会**阻断提交**（pre-commit 门禁）；每日巡检（22:30）会在 QQ 报给主人并让 Momo 感知。
- 黄项：不阻断，只提示，提醒你补元数据。

## 5. 报告方式（按主人定案）

1. 启动自检日志（bridge.log，开发者看）
2. 提交门禁（check.js，红项阻断提交，不打扰主人）
3. **QQ 命令 `/插件体检`**（主人主动问）
4. 身体面板健康徽章（P3 落地，鼠标开面板即看）
5. **每日定时巡检**（22:30，无问题不打扰；有问题 QQ 报 + 写 journal 让 Momo 感知）
6. **落盘报告** `data/plugin-health.json`（每次校验都写，机器排查用）

## 6. 归因（attribution）

借鉴外部代码/开源项目时，必须在插件里写：

```js
attribution: {
  source: "https://github.com/xxx/yyy",   // 借鉴来源
  license: "MIT",                          // 来源许可证
  note: "借鉴了它的 manifest 结构",         // 借鉴了什么
}
```

借鉴开源必须保留原许可证；自己原创的不用写。归因总表统一在 `docs/attribution.md`（身体 + 插件）。

## 7. 相关文件

- `scripts/plugin-doctor.js` — 体检逻辑（单一职责，四处复用）
- `scripts/scaffold-plugin.js` — 脚手架，`node scripts/scaffold-plugin.js <领域-用途>` 生成带完整清单的模板
- `check.js` — pre-commit 自检（含体检第 4 节）
- `plugins/plugin-doctor.js` — 体检插件（工具/命令/巡检/落盘）
- `Momo插件平台巩固优化方案.md`（MomoWork 目录）— 完整方案与 P1~P5 路线

## 8. 进化层自改代码（self-*.js）

Momo 自改进化层（`plugins/evolution.js` 的 `selfModify`）生成 `plugins/self-*.js` 时，模板同样带完整清单：

- `attribution.source` 固定为 `"self-generated by Momo"`（非开源借鉴）
- `engines.kernel` 写**当前内核版本**（防她生成未来版本才跑得动的代码）
- 其余字段（displayName/description/permissions/requires/apiSpec）与手写插件同要求，体检门禁一视同仁

## 9. 分人守则（2026-11-13 起强制）

任何新插件/新功能，只要涉及「人」，必须过下面六条：

1. **称呼一律 `_ctx.resolveCall(userId)`**：禁止写死「主人」；「主人」是唯一专属称呼（QQ 以 `cfg.qq.master_user` 为准）。
2. **注入上下文的文本先想 userId 视角**：给朋友拼的上下文里，别混进主人的画像/反思/身体感觉；给主人的上下文同理（主人的东西只给主人）。
3. **按人隔离的数据**：记忆/画像/好感度/短期记忆全部按 `<userId>` 分文件（`data/memory/<uid>.json`、`data/user-profile.json`、`data/short-memory/<uid>.json`、`data/favor.json`）；新数据也要有 userId 维度，没有 userId 维度的数据默认不注入任何对话。
4. **反思/成长注入要过滤**：只注入 `from=0`（通用）或 `from=当前userId` 的条目（见 `index.js` 的 `evolReflectionText(userId)`）。
5. **群聊带发言人**：群消息落盘带 `name`，注入历史时给 user 消息加「XX说：」前缀（见 `index.js` 的 `processGroupChat`）。
6. **权限登记**：新工具/命令必须登记 `caps.js`（未登记 = 默认仅主人）；群里 `user` 角色只放行 chat/vision/sticker（`plugins/roles.js` 的 `GROUP_USER_ALLOW`）。

> 反面教材：v1.71.x 隐私事故（身体感觉对朋友注入）、v1.90.3 抢功记忆（主人的选择被记成 Momo 的）——都是「没想 userId 视角」的产物。
