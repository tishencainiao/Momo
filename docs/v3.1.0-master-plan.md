# Momo v3.1.0「同桌陪伴：应用化与双端共同生活」总计划

状态：主刀实施与本地模拟自测完成，候选包待 DSH 独立验收；真实启动/安装替换/QQ 外部联调另行确认。

## 1. 本版目标

1. 从手动脚本/控制台变成可双击管理的 Momo 桌面应用：Node 大脑由应用托管并隐藏控制台，复用 PySide6 身体，保留单实例、托盘与明确退出。
2. 桌宠成为电脑前主要聊天入口，QQ 是离开电脑后的延续；同一主人共享必要对话与共同活动，群聊/访客数据不混入。
3. 从「她自己玩」转向「一起玩」：轮流故事、文字解谜、共同阅读/观看清单；活动可暂停、续接、换主题、彻底退出。
4. 对话围绕共同经历与当前需要，不增加追问、打卡、亲密度、回复义务或情感惩罚。
5. 默认截图关闭；窗口标题默认开启；身体右键免打扰。免打扰时不采集新标题、不主动弹气泡。
6. 一个预算中心：主界面、QQ `/预算`、自然语言工具走同一修改链；所有功能与 23 点报告读取实时预算。
7. 不设「无互动日」或一元硬配额。三元生活费时基础自主消耗约一元仅为调参期望；聊天、进化可更多，但不能突破现有硬上限。

## 2. 架构与边界

- `body/`：应用外壳、主界面、桌宠聊天、托盘、进程管理、本地感知。
- `index.js`：本地应用 HTTP 接口；统一预算修改；主人共享上下文与主动路由接入。
- `plugins/companion-service.js`：主人共享空间、对话需求分类、共同活动状态机、主动单渠道路由。
- `plugins/life-service.js` / `action-intents.js`：复用现有节律与意图恢复，不重复建后台循环。
- `plugins/budget-service.js`：仍是余额、计费、档位的唯一服务。
- 真实 QQ 发送、重启、发布、迁移真实数据、安装替换不在模拟测试中执行。

## 3. 实施顺序

### A. 应用外壳与感知门禁

- 新增主控制窗口：运行状态、聊天、显示身体、启动/停止/重启、设置、日志、退出。
- 进程操作只针对 Momo 自己的大脑/守护；关闭主窗口默认隐藏，明确退出才结束。
- 主界面可输入生活费并显示当前额度/消耗/剩余/档位；调用统一预算接口。
- 新增桌宠文字聊天窗口：本地 3999 联脑、event_id、超时与重试提示，不在身体内直接调 DeepSeek。
- 身体右键增加聊天、主界面、免打扰。
- 感知层集中执行截图、标题、免打扰、锁屏门禁；不保存键盘内容/鼠标轨迹/长期标题历史。

### B. 主人共享空间与共同活动

- 仅 `owner` scope 共享必要最近对话、摘要、共同活动；`pet` 与主人 QQ 私聊可写，群聊/访客不可写。
- 普通回复回到发起渠道，不双发。普通主动消息只选桌面或 QQ 一个渠道，桌面失败不立刻补发 QQ。
- 活动记录含 `activity_id/type/title/state/version/turn/progress/updated_at/channel`；通过版本号避免旧写覆盖新写。
- 活动支持开始、推进、暂停、续接、换主题、结束；不生成强制任务。
- 记忆修改/删除/不再提起沿用现有 continuity 与 owner 数据边界，不另造不可控长期记忆。

### C. 陪伴对话与自然消耗

- 本地需求分类：闲聊、倾听、安静陪伴、一起玩、解决问题；用于提示词约束，不替代模型理解。
- 减少连续查户口式提问，允许短回复与自然收尾；共同活动优先于高成本独自娱乐。
- 复用现有预算档位、冷却、行动意图与硬上限；无价值窗口标题变化不触发模型。
- 频率通过免费本地状态、较长冷却和活动复用降低；不写死一元目标，不伪造长期成本实测。

### D. 打包候选与交付

- 提供 PyInstaller 配置/构建脚本和启动入口；源码模式与打包模式共用外部 `data/`。
- 保留用户配置、记忆、活动数据，不在升级脚本中清空。
- 生成 v3.1.0 验收记录、完整矩阵、已知限制与 DSH 独立验收说明。
