# Momo 娱乐活动方案 v2（已按主人 5 条口径重写）

> 2026-11-05 · 状态：**v1~v4 已全部落地（v1.62.0）**，细节与实测见 `docs/changelog/2026-11.md`；上一版 v1「听歌写乐评」已回滚（v1.61.1）
> 前置阅读：`docs/vision.md` 第 6 节「她的一天不完全依赖主人在线」

> **落地结果（2026-11-05，v1.62.0）**：`read_article` 读一篇文章 / `play_puzzle` 玩数独（默认四宫格，带候选数表）/ `read_buzz` 刷热搜 / 爱好档案 + 收藏夹全部上线，娱乐产出进静默准备池（≤1 条/天）。
> 实测修正：① flash 解六宫格失败率高 → 默认四宫格 + 给"按规则推出的候选数表"（不是答案），三手全对；② 正文提取会带整行导航 → 加导航词计数过滤；③ 模型会重复填已填过的格 → 每步反馈上一手被拒原因。

## 0. 主人已定的口径（不可改）

| # | 口径 |
|---|---|
| 1 | **只做字面真实的活动**：读文本、写东西、联网搜索、文字游戏。命名必须即事实承诺（读歌词 ≠ 听歌） |
| 2 | 允许**轻量抓正文**（白名单站点，反爬直接跳过，不做常驻浏览器） |
| 3 | 游戏要**带状态、能连续玩**（存档、跨天、有进度感） |
| 4 | **情绪驱动**节律，不排固定日程表 |
| 5 | 娱乐预算 **¥0.3/天**；一天自娱 **1~2 次**；主动分享 **≤1 条/天**；产物进日记 + 记忆，慢慢形成**长期爱好**；暂不做「一起玩」 |

## 0.1 准入判据（每条活动上线前必过）

1. 动作是「真的发生了那件事」，还是「模型根据文字演绎那件事」？
2. 主人追问细节时，她拿得出真实凭据吗？
3. `current-activity.json` / 日记里写的那句话，字面是不是真的？

## 1. 设计主张

**把她真实读到的东西，变成自己的话，并留下可追溯的痕迹。**

让她接近电子生命的关键不是"读得多"，是三件事：**挑食**（会喜欢某类、不喜欢的就不读）、**有叙事**（今天读的能进日记、明天还能接上）、**有连续进行中的事**（一局数独玩到第 12 步，明天接着填）。

机器人刷内容不挑食、不留自我叙事、不积累偏好；她要的是反过来。

## 2. 活动菜单（3 个 + 1 个顺手收藏）

| 动作名 | 她具体做什么 | 真实凭据 | 产出落点 | 成本/上限 |
|---|---|---|---|---|
| **read_article** 读一篇文章 | 从白名单列表页取一篇文章链接 → 抓详情页、取 `<p>` 段落拼正文（去导航噪声，截 3000 字）→ 读 → 写「我读到了什么 + 我怎么想」（≤120 字） | `title` / `source` / `url` / `body_len` / `excerpt`（真抓到的首段 ≤200 字） | `self/reflections.json`（`from:"read"`）+ `self/journal.json` + 短期记忆 | mid；1 次/天 |
| **play_puzzle** 玩一局谜题 | 载入存档（无则代码生成）→ 每次决策一步 → **代码判定对错** → 写回存档 → 卡住可申请提示 | `puzzle_id` / `board` / `moves[{r,c,v,ok}]` / `progress` / `status` | `data/puzzle.json` + journal + reflections | low；1 次/天，每次最多 3 步 |
| **read_buzz** 吃瓜 | 拉百度热搜榜 / 取一条标题 + 热评 → 只写「我的看法」，不复述原文 | `board` / `rank` / `title` / `view`（她的看法） | `data/buzz.jsonl` + 短期记忆 | low；1 次/天 |
| 收藏（顺手，不单占次数） | 活动里真读到的好句子、歌词、梗，存进收藏夹 | `quote` + `source_url` + `ts` | `self/collection.json` | 0；随活动触发 |

**关于「写东西」**：先不单独做。现在已有 `reflect`（反思）和 `journal` 在写，再加一个 `write_thing` 会重复造轮子。等读长文跑顺了，再让「读」和「写」合流。

**她能真说出口的台词（示例）**：
- 读完一篇："我刚读完爱范儿那篇讲苹果开屏广告的，三千多字，那个『限制动作数据』的开关我居然不知道。"
- 吃瓜："百度热搜第一条挺无语的，我只看了标题和热评，没细看，就想说两句。"
- 玩谜题："那局数独我填到第 12 格，今天卡住了，明天接着来。"

## 3. 游戏：带状态、跨天、代码判定

**MVP 选谜题但先做简单档**（这一条是对 pro 原方案的修正）：

- 候选：四宫格/六宫格数独、猜词（Wordle 式）、2048。
- **推荐：六宫格数独，或四宫格起手**。理由：flash 解 9×9 数独的准确率很低，硬上标准数独很可能让她天天填错、娱乐变成折磨；四宫格/六宫格能真的做对，才谈得上"赢了的情绪"。
- 每步由**代码**校验（行列宫冲突 + 与唯一解比对），模型只负责"填哪一格填什么"。

**存档结构**（`data/puzzle.json`）：

```json
{
  "puzzle_id": "sudoku6-20261105-01",
  "size": 6,
  "givens": [[0,0,3]],
  "board": [[3,0,0,0,0,0]],
  "moves": [{"ts": 0, "r": 0, "c": 1, "v": 4, "ok": true}],
  "status": "playing",
  "progress": "5/12 格",
  "hints_used": 0,
  "stuck_strike": 0,
  "last_played": 0
}
```

**三条锁（防"她说自己玩过了"）**：
1. 局面由代码生成，答案 `solution` 只存不喂给模型；
2. 判定只由代码做，模型输出 (r,c,v) → 代码返回 ok 并写进 `moves`；
3. 只有 `status` 被代码置为 `solved` 之后，她才允许说"我解出来了"。

**卡住怎么办（必须有出口）**：
- 连续 3 次填错 → `status: "stuck"`，日记诚实记「这局卡住了」，明天盘面不变接着玩；
- 或者她"查提示"：代码给一格候选（真实动作），记 `hints_used += 1`，她可以说「我卡住了，试了试提示」——**这是真事，可以明说**；
- 一周没动 → 自动归档到"没解出来的局"，记一笔，不装作解开了。

**情绪联动**：填对 `mood +1`、`boredom -5`；填错 `boredom +3`；`solved` 时 `mood +5` 以上，并写进成长记忆（"我完整解出过一局六宫格"）。

## 4. 从"做过的事"到"爱好"

兴趣档案 `self/interests.json`：

```json
{
  "interests": [
    {"key": "AI 类长文", "type": "read", "count": 3,
     "days": ["2026-11-05", "2026-11-07", "2026-11-08"],
     "evidence": [{"ts": 0, "source": "爱范儿", "title": "...", "url": "..."}],
     "level": "hobby", "confidence": 0.75, "last_seen": 0}
  ],
  "pending": [{"key": "数独", "type": "play", "count": 1, "days": ["2026-11-05"]}]
}
```

规则：
- 每次活动顺带打 1 个 `topic` 标签（读文=主题，吃瓜=话题，谜题=固定"谜题"）；
- **≥3 次证据 且 跨 ≥2 天 → 从 pending 升为 hobby**（防"听了一次就永远喜欢"）；
- 30 天无新证据开始降信心，60 天降回 pending 归档；
- **只把 hobby 前 2 个注入上下文**（一句话："你最近的爱好：AI 类长文、谜题"），pending 一律不注入，避免稀释注意力；
- 每晚 22:00 记忆消化（digest）按主题聚合同类反思，爱好的证据链跨天累积，不是模型单次嘴硬。

一周后的样子（例子）：D1 读爱范儿 AI 文 → D3 读中新网 AI 政策 → D4 再读一篇 AI → 升为爱好；D7 她无聊时会自己冒出「再去找篇 AI 的读读」，日记里写「我最近一直在追 AI 的新闻」——**这句是真的**，背后有三条凭据。

## 5. 节律（情绪驱动）

```
想玩分 = urge×0.4 + boredom×0.4 +（心情好时 +10）
```

- 想玩分过阈值、且没超过当天上限（**总次数 1~2 次硬上限，优先于各类日上限**）才允许选娱乐动作；
- 具体玩哪个由现有 `deliberateMind` 打分决定，但上下文里要注入「上次玩的是哪个、那局到第几步」，避免连刷同一种；
- 深夜（0-7 点）不调外部站点、不分享；主人在忙时只做安静的活动（读/谜题），不做分享；
- **产出才算数**：一次娱乐如果没有留下任何产物，记失败并且**照样占当天次数**，堵住"占预算不产出"。

## 6. 接入点（最小改动、可回滚）

**新增插件**：`read-article.js`（抓正文 + 感想）、`puzzle.js`（谜题生成/判定/存档）、`buzz.js`（热搜）、`hobby.js`（兴趣档案 + 注入）。

**改 `index.js` 5 处**：
1. `ACTION_COST`：加 `read_article:"mid"`、`play_puzzle:"low"`、`read_buzz:"low"`；
2. `budgetLevelText` 的 allowed 列表加这 3 个；
3. `deliberateMind`：action 枚举加这 3 个 + 注入「最近的爱好」「那局谜题到第几步」「今日娱乐还剩 ¥x」；
4. `runMindAction`：`_actMap` 加文案（"在读一篇文章"/"在玩一局谜题"/"在看热搜"），加 3 个分发分支；
5. 娱乐子预算常量 `ENTERTAIN_CAP = 0.3`，超了就过滤娱乐动作。

**life-log** 加两行：读 `data/puzzle.json`（"最近在玩谜题，到第 X 步"）、`data/buzz.jsonl`。
**proactive**：娱乐感想进"可分享池"，一天最多发 1 条，走现有静默/频率/打扰门禁。
**新增 settings**：`entertainment.daily_cny=0.3`、`daily_self_max=2`、`puzzle_moves_per_day=3`、`interest_min_evidence=3`、`interest_min_days=2`。

最贵组合 ≈ **¥0.02/天**，离 ¥0.3 上限很远（上限是给将来加活动留的余量）。

**降级顺序**：内容源挂了 → 换下一个白名单源 → 全挂就诚实记「今天想读但没读到」（不算产出、不占预算）→ 预算 tight 只玩谜题/吃瓜 → 预算 empty 全停。

## 8. 版本拆分与验收

| 版本 | 内容 | 正例 | 反例 |
|---|---|---|---|
| **v1 读一篇文章**（推荐先做） | read-article.js + index 接入 + reflections 落点 | 日志有真实 HTTP；正文 ≥1500 字；reflections 里带 title/url/body_len/excerpt；她说的细节都能在 excerpt 里对上 | 没抓到就说"我读了一篇"；把搜索摘要当正文；感想里出现正文没有的内容 |
| **v2 谜题** | puzzle.js（六宫格/四宫格）+ 存档 + 代码判定 | `data/puzzle.json` 有 moves 且 ok 真实；solution 从未进过模型输入；解出才说"解出来了" | 模型自称解完但 status 没变；局面是模型编的；跨天存档被重置 |
| **v3 吃瓜 + 爱好档案** | buzz.js + hobby.js + 注入 | 只写看法不复述原文；3 次证据跨 2 天升 hobby；只注入 hobby 前 2 个 | 转发热搜原文；pending 提前注入；一次就升爱好 |
| **v4 分享 + 收藏** | proactive ≤1 条/天 + collection | 分享走门禁；收藏带 source_url | 一天分享 ≥2 条；收藏编造句子 |

反例检查（每版都查）：一天自娱 >2 次；同一活动连刷；预算耗尽还娱乐；娱乐无产出却占次数。

## 9. 红线与风险

- **内容安全**：长文/热搜可能低俗、敏感、谣言。她只写自己的看法，不复述敏感细节、不转发原文、不传播未经核实的信息。
- **防编造**：抓不到就明说"没读到"；感想只能基于真抓到的字段；谜题答案永不进模型输入。
- **版权与礼貌**：只存 `title + url + ≤200 字 excerpt`（引用性质），**不存全文**；同源请求间隔 ≥30 秒；403 直接跳过。
- **站点失效**：抓取逻辑集中在 `read-article.js` 的源表里，挂了改一处，不做通用爬虫。
- **娱乐挤占陪伴**：主人消息优先，娱乐可被打断；分享 ≤1 条/天；深夜不打扰。

## 10. 明确不做

虚拟世界 / 常驻浏览器 / 音视频 / 图像生成 / 付费 API / npm 包 / 给主人做配置界面 / 常驻爬虫 / "一起玩"（只留字段位）。

## 11. MVP 第一刀

**推荐：`read_article` 读一篇文章**（不是 pro 原方案建议的谜题，理由如下）：

- 主人的核心诉求是"得到反馈、充实个人记忆和人格"——读长文直接产出：一篇真读过的文 + 一段她自己的看法 + 一条可追溯的记忆，还能长成"阅读爱好"；
- 谜题的价值是"真的在玩、有连续进度"，但它对记忆和人设的贡献是单一的（"我爱谜题"），更适合作为第二版；
- 风险是站点失效——所以先做**多源 fallback**（爱范儿 → 简书 → 中新网），并且抓不到就诚实记失败。

**当天验收**：
1. `self/reflections.json` 新增一条，`from:"read"`，带 title/url/body_len；
2. `self/journal.json` 新增一条"今天读了什么"；
3. `data/`（或 `self/`）里有对应记录，`body_len ≥ 1500`；
4. 打开那条 url，标题和 excerpt 与正文一致；
5. 问她"你今天读了什么"，她能说出标题+一句真实感想，且不出现正文里没有的内容。
