# Momo 娱乐活动系统方案（待主人拍板）

> 2026-11-05 · 状态：v1.61（听歌写乐评）已落地，v1.62+ 未开工 · 调研记录见文末
> 前置阅读：docs/vision.md 第 6 节「她的一天不完全依赖主人在线」、docs/roadmap.md

## 1. 设计主张

娱乐系统不是「多接几个 API」，而是把**「自我生成」这条营养源长出来**。

每个娱乐动作必须同时满足三件事：

1. **真做了**——真调了接口，拿到了歌词 / 热评 / 榜单 / 热搜；
2. **留了东西**——乐评、谜题、小诗、歌单，带 `source` 可追溯；
3. **回流**——变成她的品味、她的记忆、她跟主人聊天时的话题。

闭环：**她玩过 → 她喜欢 → 她下次会聊 → 她更有自我**。

反面：给一张虚构日程表（「今天下午在看剧」），这是现在产品红线明确禁止的（不许编造经历）。

## 2. 活动菜单

### A 类：自娱（主人不在线时她自己玩）

| 动作名 | 她具体做什么 | 数据源 | 产出去哪 | 单次成本 | 上限 |
|---|---|---|---|---|---|
| `music_review` 听歌写乐评 | 从榜单挑一首 → 拉歌词 + 热评 → 写 2-4 句乐评 → 给品味投一票 | 网易云（榜单 / 歌词 / 热评） | `data/activities.jsonl` + `data/taste.json`，偶尔配图发空间 | 2 次 flash ≈ ¥0.003 | 1-2/天 |
| `hot_peek` 追热搜吃瓜 | 拉实时热搜 → 挑一条她关心的 → 写一句感想存着当谈资（不转发原文） | 百度热搜榜（+ HN 可选） | `data/fun-stuff.json`、`mind.json` 念头 | 1 次 flash ≈ ¥0.0015 | 1/天 |
| `comments_crawl` 逛评论区 | 读她最近听的歌的高赞评论 → 写「戳中我的那条 + 我的感受」 | 网易云热评 | `taste.json`、可选 `reflections.json` | 1 次 flash | 1/天 |
| `solo_game` 自己出题玩 | 出一道 24 点 / 猜词 / 文字推理，自己解出来并判对错，存成题库以后考主人 | 纯自生成 | `data/fun-stuff.json`（题 + 答案 + 解） | 2 次 flash ≈ ¥0.003 | 1/天 |
| `scribble` 写小诗 / 碎碎念 | 基于**当天真实发生的事**（念头、搜到的、听过的）写一段，沉进日记 | 纯自生成 | `self/journal.json` | 1 次 flash | 1/天 |
| 刷视频（已有 `browse`） | 扩展：顺手把「喜欢什么类型」写进品味 | B 站热门 | 已有 `browse.jsonl` + `taste.json` | 已有 | 已有 3/天 |

### B 类：和主人一起玩（主人能在 QQ 里真触发）

| 触发词 | 她做什么 |
|---|---|
| 「一起听歌」 | 按她的品味挑一首 → 发歌名 + 歌手 + 一段歌词 + 一条热评 → 顺着歌词聊（**诚实**：她不能真播放，是"一起读同一首歌"） |
| 「猜谜」「猜歌」 | 她出题（用 `solo_game` 攒的题）主人答；或主人给歌词片段她猜歌名（网易云搜索自己验证） |
| 「接龙」 | 一人一句轮流编故事，她续写并记结局 |
| 「斗图」 | 复用已有表情包库 + `share_fun` |

B 类不进心跳循环，由聊天入口触发；她也可以主动提议一次，但必须过 proactive 门禁（静默时段、频率、打扰门禁）。

## 3. 节律设计（不是日程表）

真实活动的作息概率曲线，由已有的 `urge`（想做事的程度）+ `boredom`（无聊度）+ 时段驱动：

```
权重 = 时段偏好 × (0.5 + 0.5×urge/100) × (0.4 + 0.6×boredom/100) × (今天做过该活动 ? 0.3 : 1.0)
```

| 时段 | 偏好 |
|---|---|
| 06-11 早 | 追热搜、晨间碎碎念 |
| 11-14 午 | 听歌、逛评论 |
| 14-18 下午 | 自玩出题、听歌 |
| 18-22 晚 | 刷视频（已有） |
| 22-06 深夜 | 写日记、反思——**不调外部接口、不发消息** |

防假忙碌四条：①接口失败记 `source=failed`，不算玩过；②A 类每天硬上限 3 次、间隔 ≥1 小时；③深夜只做纯自生成；④「我刚听了 X」只能出现在当天真的跑成功之后。

**补充（本方案额外要求）**：娱乐结束要有即时反馈——降低无聊度、轻微改变心情（听治愈的歌心情涨、刷到让人生气的热搜心情掉），否则「她在玩」对体感没有意义。同时写 `current-activity.json`，这样主人问「你在干嘛」她能答真话。

## 4. 品味系统（灵魂）

存 `data/taste.json`，是「我喜欢什么」的证据账本（简化版，避免过度工程）：

```json
{
  "music": [
    {"id": "31877471", "title": "安河桥", "artist": "宋冬野", "rating": 0.7,
     "tags": ["民谣", "叙事"], "plays": 2, "first_ts": 0, "last_ts": 0}
  ],
  "tags": [
    {"tag": "民谣", "weight": 0.6, "evidence": ["song:31877471", "song:186016"], "days": ["2026-11-05"]}
  ],
  "topics": [{"tag": "游戏", "weight": 0.4}],
  "games": [{"tag": "24点", "weight": 0.5}],
  "mood": [{"tag": "最近有点上头", "expires": 0}]
}
```

三条硬规则：

1. **去重**：key = 歌曲 id / 话题词，同一 key 只累加证据，不重复建条目。
2. **防单次绑架**：一个标签要算「我喜欢」，需要 `evidence ≥ 3` 且**跨 ≥2 天**。一天的连续情绪只进 `mood`（带过期时间），注入时注明「最近有点上头」，**永不**写进永久品味。听了首悲伤的歌 → 只会「最近情绪有点低」，不会「我永远喜欢悲伤」。
3. **注入**：只注入 top-3 标签 + 最近一次活动摘要，不要全量塞进上下文（避免注意力稀释，这是 vision.md 里已列的问题）。

与记忆消化联动：digest 读 `taste.json`，把品味合成「主题认知」；每攒 N 次活动写一条 `reflections.json`（`from: "taste"`）。

## 5. 接入点（最小改动、可回滚）

- **新增插件**：`plugins/music.js`（网易云三个接口的纯封装，无副作用）、`plugins/entertainment.js`（A 类动作 + 节律 + taste 读写）、`plugins/play.js`（B 类响应式）。
- **改 `index.js`**：`deliberateMind` 的候选动作加 A 类 5 个名字；`ACTION_COST` 加档（`solo_game`/`scribble` = free，另三个 = low）；`runMindAction` 加 5 个分支。
- **改 `browse.js`**：顺手写 taste。
- **改 `life-log.js`**：读 `taste.json` 摘要 + `activities.jsonl` 最近 3 条。
- **不动** `evolution.js`、`digest.py`（taste 联动放到 v1.62 再改 digest）。
- **回滚**：删三个插件 + 去掉 mindLoop 的 case，不影响其它功能。

## 6. 成本

| 项 | 值 |
|---|---|
| 娱乐日预算上限 | ¥0.15（总预算 ¥2 的 7.5%） |
| 典型一天实际 | 3 次活动 ≈ 5 次 flash ≈ ¥0.008 |
| 降级顺序 | 砍 search → 砍带接口的 → 只留写日记 → 全停 |

| 版本 | 改什么 | 验收正例 | 验收反例 |
|---|---|---|---|
| v1.61 ✅ | 只做听歌写乐评（`music.js` + `music_review` + `activities.jsonl`） | 日志里有真实 HTTP 返回；乐评引用的是接口真给的词句；记录带 songid | 没调接口就写「我听了 X」；编造热评；一天刷多首但毫无沉淀 |

## 8. 红线

- **内容安全**：热搜 / 热评可能含低俗、政治敏感、负面情绪。她只「转述观点 + 评价」，不转发原文；生成时加安全约束；负面内容只记感受，不放大。
- **防刷屏**：一切出站走 proactive 门禁；娱乐话题分享 ≤1-2 条/天。
- **防假装**：没有真实返回就没有产出。
- **防过度拟人**：措辞用「我翻了翻 / 我读到」，不用「我听见了 / 我看见了」这类虚假感官。
- **陪伴优先**：主人消息一到，娱乐立即让位；分享只在主人歇口气的窗口。

## 9. 明确不做

自建虚拟世界 / 沙盒游戏、真玩客户端游戏（llm-game-automation-mcp 那类过重）、图像或音频生成、真播放音视频、引入 npm 包或付费 API、给用户做「兴趣配置界面」（品味必须自动沉淀、零维护）。

## 10. MVP 第一刀

**只做 `music_review`**：接口已实测可用、成本最低、产出最像她、顺手就能长出品味雏形。

当天验收：手动触发一次 → ①有真实 HTTP 返回；②`activities.jsonl` 新增一条带 songid 的乐评；③乐评只引用接口真返回的词句。
