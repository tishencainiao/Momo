# 0003 · 三层插件架构

- 日期：2026-10（v1.11 起逐步迁移，到 v1.46 为 31 个插件）
- 状态：已采纳

## 背景

早期所有功能都写在一个 `index.js` 里（一度超过 3600 行），改一处要担心影响别处；
新功能没法单独关掉，也没法热重载。

## 决定

| 层 | 位置 | 职责 |
|---|---|---|
| 基础层 | `index.js` | 消息接入 / agent 循环 / 数据存储 / 预算 / 权限 / 插件分发 |
| 插件层 | `plugins/*.js` | 具体功能；用 `ctx` 取内核能力，用 `api` 暴露能力给别的插件 |
| 进化层 | `plugins/evolution.js` + `self/` | 自我内省、反思、技能规则、受限自改 |

配套约定：

- 插件之间**不直接 require**，一律 `ctx.getApi("<名字>")`
- 内核只保留"多层共用"的东西，具体业务一律下沉到插件
- 每个插件声明 `settings`，让参数可配、能在 QQ 里改
- 插件支持热重载（监听 `plugins/`）

## 后果

- 加功能 = 加一个文件，不动内核。
- 副作用：插件容易重复（曾经同时存在两个体检入口 `self_check` / `health_check`，v1.44 才合并），需要定期清理。
- 副作用：跨插件调用链要自己查清楚，改之前必须确认"谁在调我"（见 development.md 第七节）。
