# 0007 · 防捏造：能力负清单 + 输出后审计 + 记忆事实分层

- 状态：已实施（v1.63.0，2026-11-05）
- 来源：2026-11-05 21:25 事故（她说"我这就放给你听"并演了两分钟，实际没有播放能力）
- 根因诊断：见 0006 同批记录；方案：`docs/fabrication-guard-plan.md`

## 决定

把「自我陈述」和「可验证事实」分层，设三道防线：

| 防线 | 实现 | 拦什么 |
|---|---|---|
| 写回前校验 | `evolution.looksLikeUnverifiedDeed`、`memory.dropAgentDeeds`、`digest.py` 的 `AGENT_DEED_RE`、用户画像过滤 | 「我想做/我在攒」不许落盘成「我已经有/我做到了」 |
| 上下文标注 | `identity` 的 `kind/verified`、pending-nudges 的 `fact:false/source`、注入框改写 | 待办不许升格为"已具备" |
| 输出后审计 | `fabrication-guard.js` + `agentChatOnce` 的工具台账 | 说了要做到的事、但本轮没有工具兑现，直接拦下 |

## 审计的两条判别（都是确定性规则，不调模型）

1. **否定判别**：同一分句里有「不/没/别/无法/不能/做不到/两码事/不是…」→ 她在否认，不算编造。否则会把「放歌做不了」这种真话换成道歉。
2. **模糊词需上下文**：「放啦 / 我开始了 / 放好了」只有在同句或紧邻句出现「歌/音乐/这首/旋律」等词时才拦，避免误伤「钥匙放好了」。

## 负清单（可扩展）

内置：播放音乐/音频、真的唱歌、看视频画面。主人确认后可写 `data/capability-limits.json` 追加。
同一能力被拦/被纠正累计 2 次 → `data/capability-proposals.json` 生成提案，等主人确认。

## 明确不做

- 每次回复请 LLM 裁判（+1 调用，顶穿预算）
- 全量工具调用数据库（内存台账够用）
- 用模型判断"这句是不是声明"（关键词确定性）
- 硬删污染数据（一律归档到 `data/archive/`）

## 验收（已通过）

- `test/fabrication-guard.js` 33 断言：编造拦截、诚实否认不误拦、「钥匙放好了」不误伤、负清单注入与提案、成长记忆闸、记忆过滤、清理脚本 dry-run 不写盘
- 真实提示 + 真实模型：问「你还能放歌的吗」→ 她如实说做不到；说「放首歌」→ 如实说做不到；两次都没被误拦
