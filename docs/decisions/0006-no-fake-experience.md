# 0006 · 娱乐活动的准入判据：不许用文字演绎冒充经历

- 状态：已生效（2026-11-05，v1.61.1）
- 背景：v1.61.0 上线了「听歌写乐评」——从网易云拉榜单、歌词文本、热评文本，让模型写一段感想，并把当前活动写成「在听歌写乐评」。上线后主人当场追问「这是真的听了吗」，答案是**没有**。
- 结果：v1.61.0 已回滚，代码回到 v1.60.0 行为。

## 出了什么问题

| 层 | 问题 |
|---|---|
| 事实层 | 整条链路只读到了文字（歌词 + 评论），没有任何音频播放、没有听感。她「理解」这首歌靠的是读歌词。 |
| 行为层 | `current-activity.json` 写「在听歌写乐评」，值日注入她的上下文 → 被问「你在干嘛」她会说「我在听歌」。这是假经历。 |
| 数据层 | `taste.json` 记成「喜欢这首歌 / 喜欢这个歌手」，实际只是读了歌词，品味会被污染成「像文案的假偏好」。 |
| 生成层 | 乐评写得像真的一样（模型能根据歌名和歌词演绎），越像越容易让人误以为她真经历了。 |

## 判据（以后所有「她自己的娱乐/生活」功能都按这三问过）

1. **动作是"真的发生了那件事"，还是"模型根据文字演绎那件事"？**
   只有前者能算经历；后者必须如实命名（读歌词 ≠ 听歌，看简介 ≠ 看视频）。
2. **主人追问细节时，她能拿出真实凭据吗？**
   拿不出（比如"旋律很抓耳"而她拿不到音频）就不许说。
3. **`current-activity.json` / journal / 记忆里写的那句话，是否字面为真？**
   这句话会被注入对话，等于她的口径，必须字面成立。

## 落地要求

- 新活动上线前，先在 `docs/entertainment-plan.md` 的活动表里写清「她具体做了什么动作」与「她能拿出的凭据字段」。
- 涉及"感官"（听/看/闻/尝/触）的活动，默认不成立——Momo 没有音视频流、没有听觉；除非真的接了对应输入（例如桌宠的屏幕截图 + 视觉模型），否则一律改写成文字动作。
- 活动命名即事实承诺：`翻歌词本` 可以，`听歌` 不行。
