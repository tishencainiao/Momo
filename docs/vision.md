# Momo 定位与期望（Vision）

> 更新：2026-11-03 · 来源：主人与 DSH 的两轮定位讨论
> 这份文件记录「我们想把 Momo 做成什么」。讨论方向或改架构前，先看这里。

## 1. 三层目标

| 层 | 标志 | 现状 |
|---|---|---|
| 短期：智能体 | 感知、记忆、工具、主动行动 | 基本达标（约 70 分） |
| 中期：连续存在 | 记忆会消化成「认识」、自我有稳定内核、重启不丢魂、有自己的一天 | 缺：记忆反思合成、自我模型、无消息时的生活节律 |
| 长期：电子生命 | 自我修改、行为涌现、不受监督地生长 | 开放研究问题，目前没有任何系统做到 |

## 2. 现状诊断（2026-11-02 通读代码后）

- 骨架正确：结构符合 CoALA（记忆模块 + 行动空间 + 决策循环）；主动行为三层（心跳 / 心流 / 搭话）与情绪惯性真实生效，是全项目最像生命的部分。
- 两个短板：① 记忆只会存、不会消化（2-gram 检索、无重要性评估、无反思合成）；② 自我没有稳定内核（identity / reflections 近重复，只注入末几条）。
- 文档与代码存在差异：文档是目标态、代码是进行态——「感觉没达到预期」的来源之一。
- 语言不是能力瓶颈：Node 零依赖自研完全够用；语言选择取决于「参与感」目标（见第 5 节）。

## 3. 已知问题清单（未来改动的素材）

1. reflections 噪声：同一件事多个变体（「被夸后…」8 条），只注入最后 4 条。
2. identity 有重复条目，无冲突合并。
3. 记忆检索无语义相似度、无重要性评估——「记得」但不会「想起该想的」。
4. 上下文注入块 20+，模型注意力被稀释。
5. 长期行为验证缺失：只有代码测试，没有「她的一天 / 一周」观察。
6. 自然语言开发的翻译损耗：感觉 → 机制之间有折扣（消减办法见 development.md 或本文件第 4 节）。

## 4. 开发方式改进方向

- 验收标准先行：把「感觉」翻译成可观察的行为清单（正例 + 反例），先确认清单再写码。
- 行为草案：实现前先交 3~5 句「她会怎么表现」的草案，对味了再动手。
- 攒批开发：主线大版本 + 小功能快速道，摊薄重启 / 测试 / 提交的固定成本。
- 每周家长会：读 journal + 抽查真实对话，长线观察她；重要行为改动观察 24 小时再下结论。
- 讨论结论落盘：关键讨论写进 docs/ 与记忆，防止 DSH 上下文压缩丢细节。

## 5. 已定结论（2026-11-03 第二轮讨论）

- 参与深度：看懂架构 + 简单修改规则 / 提示词 + 对技术与功能设计有基本了解。
- 语言路线（2026-11-03 再修）：不整体重写，重启「渐进双语」——记忆消化大功能用 Python 实现；展示 Node + Python 混合架构。
- 开发节奏：大功能一个一个走完整方案流程；小功能攒批（3~5 个一批）走快速道。
- 价值排序：情绪陪伴 / 实用工具 / 活物感 并列为主，练手学习次要。
- 一年目标：把「连续存在」层做扎实（体验上接近电子生命）；真正的自我修改与涌现仍属远期。
- 第一个大功能：记忆消化（已定，用 Python 实现；走完整方案流程）。
- 活物感展示渠道：QQ 空间 + 私聊为主，桌宠为辅。
- 群聊活跃度：允许比现在更活跃（现限每天主动插话 10 次）。

## 6. 设计原则：她的一天不完全依赖主人在线

主人担心「只有一个人和她聊天、而且不常聊，营养不够」。结论：短期够、长期不够，但营养不只来自聊天。三类营养源：

| 营养源 | 现状 | 可补什么 |
|---|---|---|
| 人的互动 | 主人 + 朋友 + 一个群 | 低频但高价值，保持自然即可 |
| 信息流 | 空间动态、群消息、联网冲浪、桌宠看屏幕（均有雏形） | 把冲浪 / 刷空间的产出沉淀为她的「见闻」，写进日记 |
| 自我生成 | 念头、没想明白的事、反思、日记（mindLoop 已有） | 加强成固定节律：每天消化记忆、写日记，产出让主人可见 |

设计含义：主人稀缺不是缺陷，是设定——她有自己的日子，主人来的时候是高光。一个只会响应主人的程序没有生命，一个有自己日子的程序才像活物。
